## Что важно понимать в реализации

**Многостраничность.** Каждая страница является отдельным HTML-документом. Ссылки загружают другие документы; SPA, маршрутизатора и фреймворка нет.

**Семантика.** `main` содержит основное содержимое, `section` объединяет тематический раздел, `article` обозначает самостоятельную карточку, `aside` содержит фильтры или пояснения. Навигация находится в `nav`.

**Flexbox и Grid.** Flexbox удобен для одного ряда элементов, например меню. Grid задаёт строки и колонки, например сетку товаров или раскладку «фильтры + каталог».

**БЭМ.** Блок `product-card` самостоятелен, элемент `product-card__title` принадлежит карточке, модификатор `product-card--featured` меняет вариант оформления. Стили не зависят от конкретного `id`.

**Переменные и состояния.** `:root` хранит общие значения. `:hover` отвечает за мышь, `:focus-visible` показывает положение клавиатурного фокуса, `:disabled` обозначает недоступный элемент.

**Модальное окно.** `showModal()` открывает `<dialog>` поверх страницы. Браузер удерживает фокус внутри, закрывает окно по Escape и возвращает фокус к инициатору. Без JavaScript ссылка ведёт на `order.html`.

**Форма.** HTML проверяет заполненность, e-mail и формат телефона. Кнопка «Проверить заявку» выполняет учебный сценарий отправки формы методом GET и открывает страницу результата. Серверного обработчика нет. Использовать нужно вымышленные данные: значения попадают в URL.

**Статические фильтры.** По заданию это макет. Они отключены, чтобы пользователь не ожидал реального отбора. Ссылки категорий работают и прокручивают страницу до раздела.

**Повторяющаяся шапка.** В статическом HTML её разметка присутствует в каждом файле. Это позволяет открывать страницы напрямую без сборщика. Все стили при этом остаются в одном файле.
